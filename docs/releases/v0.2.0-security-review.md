## Fixed during this review

1. **Removing someone from a project didn't close their open notes at once.** SECURITY.md
   promised it; the code only re-checked every 15 seconds. Now a sharing change applies
   immediately (closed, or switched between read-only and editing), with the 15-second
   re-check kept as a backstop. Test: `test_sharing_changes_apply_to_open_notes_at_once`.
2. **Refused collaboration attempts weren't logged** (promised in §7.15). They are now a
   `collab_refused` security event, without the update's content. Test: extended
   `test_viewers_cannot_edit`.
3. **No automated test for the upload rate limit** (criterion 8). Added.
4. **No automated test for the collaboration message rate limit.** Added.

## Open items

**Unfixed critical in the base image (criteria 3 and 9).** Still CVE-2026-6653 (`libxml2`,
denial of service) in Debian 13, with no fixed version available. Nothing changed in how
PlanHaven uses it: the app never parses XML with libxml2, and PostgreSQL isn't reachable
from the network. CI fails on any critical that has a fix and re-scans weekly. Accepted for
v0.1.0; **accepted again by the maintainer on 2026-09-28 as a standing exception** for
later releases too, until Debian ships a fix (the weekly scan then fails until the image is
rebuilt).

**Known limitation: image decoding runs as the app's user.** The subprocess limits its own
resources, but it isn't yet a separate user without access to other files. That arrives
with the extraction sandbox in phase 0.5 (§7.6).

**Low: `Cross-Origin-Embedder-Policy` header missing** (ZAP). Unchanged; no cross-origin
content is used. Still planned with the plugin UI iframes (phase 0.7).

**Informational (ZAP):** "Storable and cacheable content" (the hashed app files, cached on
purpose) and "Modern web application". No action.
