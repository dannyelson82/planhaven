## Fixed during this review

1. **Wrong calendar or sync keys weren't security events, and had no per-address limit.**
   They're now logged as `key_failed`, counted by the fail2ban filter and the CrowdSec scenario
   in `deploy/` like failed sign-ins, and limited per address (only failures count, so a
   household behind one address keeps working). Keys are 256-bit, so this is about noise and
   visibility, not guessing. Tests: `test_failed_keys_are_logged_and_limited`,
   `tests/test_deploy_configs.py`.
2. **Missing tests for the sync and message rate limits** (criterion 8). Added.
3. **Chore assignments could be repeated to flood someone with alerts.** Assigning is now rate
   limited per person (`CHORE_ASSIGN`).
4. **The security document didn't describe the personal live channel**; §7.15 now does, and
   §7.17 summarises the phase's controls.

## Open items

**Unfixed critical in the base image (criteria 3 and 9).** CVE-2026-6653 (`libxml2`, denial of
service) in Debian 13, no fixed version yet. PlanHaven never parses XML with libxml2. A standing
exception accepted by the maintainer on 2026-09-28; CI fails on any critical that has a fix.

**Known limitation: image decoding runs as the app's user.** Unchanged; the extraction sandbox
in phase 0.5 gives it its own user (§7.6).

**By design: the calendar link is in a URL**, so a reverse proxy in front of PlanHaven may log
it. It's read-only, titles only by default, and can be renewed or turned off at any time (§7.3).

**By design: messages are stored like notes**, readable by whoever runs the server's database
(ADR 0018, disclosed in the guide).

**Not verified on a device: the Reminders Shortcut recipe** (functional, not security). Signed
Shortcut files need a Mac; the maintainer will try the recipe on an iPhone.

**Low: `Cross-Origin-Embedder-Policy` header missing** (ZAP). Unchanged; planned with the plugin
UI iframes (phase 0.7).
