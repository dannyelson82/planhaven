## OAuth best-practice checklist (RFC 9700, OAuth 2.1, RFC 8252)

| Practice | Status | Where |
|---|---|---|
| Authorization code only; no implicit or password grant | ✅ | `unsupported_grant_type` for anything else (`test_token_endpoint_rejects_junk`) |
| PKCE S256 required, verifier compared in constant time | ✅ | `oauth.pkce_ok`; `test_codes_and_refresh_tokens_work_once` |
| Exact redirect URI match; no open redirect for an unknown client or URI | ✅ | `oauth.redirect_allowed`, `authorize`; `test_bad_authorize_requests` |
| Codes short-lived, single use, bound to client, redirect URI and verifier; reuse revokes | ✅ | 2 minutes; `test_codes_and_refresh_tokens_work_once` |
| Mix-up defence: `iss` in the authorization response (RFC 9207) | ✅ | `oauth.approve`; checked in the test helper `_approve` |
| Audience-restricted access tokens (RFC 8707 `resource`) | ✅ | Only this server's `/mcp`; MCP tokens aren't accepted anywhere else |
| Refresh tokens for public clients rotated, with reuse revoking the family | ✅ | Revocation committed before the error; tested |
| Tokens stored hashed; token responses `Cache-Control: no-store` | ✅ | `tokens.token_hash`; tested |
| Consent can't be framed; consent needs a fresh second factor | ✅ | CSP `frame-ancestors 'none'`; `step_up` in the matrix |
| `state` passed back unchanged (length capped) | ✅ | Tested in `_approve` |
| Revocation endpoint (RFC 7009) and disconnect in the account page | ✅ | `test_apply_mode_viewer_and_disconnect` |
| Loopback redirects accept any port (RFC 8252 §7.3) | ⚠️ Not done | Exact match only; see open items |

## Fixed during this review

1. **No automated tests for the AI connector's rate limits** (criterion 8). The limits were in
   place (`OAUTH_REGISTER_IP`, `OAUTH_TOKEN_IP`, `MCP_GRANT`, `MCP_WRITE_GRANT`) but nothing
   checked them. Two tests added in `tests/db/test_ai.py`; they also show that one connection
   running out doesn't affect another.

## Open items

**Medium, build time only: `minimatch` (GHSA-g3hv-75wg-m249).** A denial of service through
crafted glob patterns, in a copy pulled in by `workbox-build` (via `glob` 11), which only globs
PlanHaven's own build output with patterns from our own config. No `glob` 11 release accepts the
fixed `minimatch` 11, so it's fixed with an npm override in its own pull request.

**Low, compatibility: loopback redirects need the exact port.** RFC 8252 §7.3 asks servers to
accept any port for `http://127.0.0.1` / `http://[::1]` redirects, since desktop apps pick a free
port each time. PlanHaven matches the registered URI exactly, so such an app has to register
again when its port changes. Not a security weakness (stricter than required); changing the
matching rule is left to the maintainer. RFC 8252 also recommends the IP literals over
`localhost`, which is still accepted.

**Not re-verified here: provenance by `gh attestation verify`.** The review's token can't read
the package registry; the release workflow that creates the attestations succeeded for each tag.

**Low: `Cross-Origin-Embedder-Policy` header missing** (ZAP). Unchanged; planned with the plugin
UI iframes.
