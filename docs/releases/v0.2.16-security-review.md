## Fixed during this review

1. **Failed share-link opens weren't security events.** Unknown, expired or turned-off links
   and wrong PINs are now logged as `share_link_failed`, and the fail2ban filter and CrowdSec
   scenario in `deploy/` count them like failed sign-ins, so guessing gets the address banned.
   Tests: `test_failed_opens_are_logged_and_pins_run_out`, `tests/test_deploy_configs.py`.
2. **Ended share-link sessions stayed in the database.** They no longer worked, but they
   piled up; the hourly maintenance job now removes them
   (`test_ended_guest_sessions_are_cleared`).
3. **No test for the per-link limit on guest changes** (criterion 8). Added
   (`test_guest_changes_are_rate_limited`).
4. **Redaction was tested for one token type only** (criterion 7). Now every type
   (`test_masks_every_token_type`).
5. **Threat model out of date** (criterion 12). The live-editing row now describes saved notes,
   the XSS row covers the in-app guide, and there are new rows for contact cards, templates,
   experimental features and suggestions.

Found and fixed earlier in this phase, while building: contact photos had the small JSON body
limit instead of the upload limit (v0.2.13), and a card dragged out of its group could be taken
over by the tile around it (v0.2.15).

## Open items

**Unfixed critical in the base image (criteria 3 and 9).** CVE-2026-6653 (`libxml2`, denial of
service) in Debian 13, no fixed version yet. PlanHaven never parses XML with libxml2, and
PostgreSQL isn't reachable from the network. A standing exception accepted by the maintainer
on 2026-09-28; CI fails on any critical that has a fix and re-scans weekly.

**Known limitation: image decoding runs as the app's user.** Still resource-limited but not a
separate user; that comes with the extraction sandbox in phase 0.5 (§7.6).

**By design: guests' photos are recorded as uploaded by the link's creator** (the account
behind the link), with the guest's name in the link's activity (ADR 0015, "As built").

**Low: `Cross-Origin-Embedder-Policy` header missing** (ZAP). Unchanged; planned with the
plugin UI iframes (phase 0.7).

**Informational (ZAP):** "Storable and cacheable content" (hashed app files, cached on purpose)
and "Modern web application". No action.
